# EduRisk v0.8 — протокол внешней проверки на OULAD

Дата протокола: 03.11.2026. Версия: 0.8.0.

## 1. Статус и источники

**Статус исполнения:** реализован код импорта и эксперимента; проверен на `SYNTHETIC_SCHEMA_FIXTURE`. **Оригинальные CSV OULAD в среде сборки отсутствуют; действительные метрики на OULAD не получены.** До выполнения протокола на подлинных файлах не называть проверку независимой эмпирической валидацией.

Оригинальный датасет: Kuzilek J., Hlosta M., Zdrahal Z. *Open University Learning Analytics dataset*, Scientific Data 4, 170171 (2017), DOI https://doi.org/10.1038/sdata.2017.171. Страница UCI: https://archive.ics.uci.edu/dataset/349/open+university+learning+analytics+dataset. Страница Open University: https://research.stem.open.ac.uk/ouanalyse/dataset/.

OULAD содержит информацию о модулях, представлениях, оценках и событиях VLE; **не содержит пятилетнюю историю семестровых оценок ТУСУР**. Это самостоятельная постановка на уровне курса.

## 2. Исследовательская постановка

**Единица наблюдения:** (код модуля, представление модуля, ID студента).

**Момент прогноза:** 84-й день обучения, считая день 0 началом представления курса. В предсказательный набор включаются обучающиеся, зарегистрированные на этот момент и не отчислившиеся (не прекратившие обучение) к этому дню.

**Прогнозируемое событие:** `final_result ∈ {Fail, Withdrawn}` против `{Pass, Distinction}`. Оно считается бинарным событием риска на момент **завершения** курса; не оцениваются причинные эффекты образовательных вмешательств.

**Варианты истории:** 14, 28, 56, 84 дня **непосредственно перед 84-м днём**, а не число предыдущих семестров.

**Признаки:** число событий VLE, сумма кликов, число доступных оцениваний, средняя оценка, разброс оценок (если имеется), число прошлых попыток, число изучаемых кредитов и дата регистрации. Не используются: `final_result`, `date_unregistration` как предиктор, демографические характеристики и идентификатор студента. Дата прекращения обучения используется только при определении, был ли студент в обучающейся когорте на 84-й день.

Оценки заданий включаются только при `date_submitted ≤ 84` и `assessments.date ≤ 84`. **Ограничение:** в OULAD нет точного момента, когда оценка стала видна преподавателю. Консервативная фильтрация по дате сдачи и сроку задания снижает, но не полностью исключает эту неопределённость.

## 3. Протокол честной проверки

1. *Train:* курсы 2013B/2013J.
2. *Validation:* 2014B; выбираются длина фиксированного окна, стратегия и параметры калибровки.
3. *Holdout:* 2014J; используется только для финальных метрик. Пересекающиеся анонимные `id_student` исключаются из предыдущих разбиений, чтобы один студент не встречался одновременно в train/validation/holdout.
4. Вычисление признаков с фильтрацией по контрольной дате. `studentVle.csv` считывается порциями (без загрузки 430+ МБ в память).
5. Четыре метода сравнения:
   - фиксированное окно с максимальной AP на валидации;
   - фиксированная безучительская функция качества каждого окна («адаптивный выбор»);
   - простое среднее вероятностей окон;
   - взвешенное среднее по преимуществу валидационной AP относительно доли положительного класса.
6. Метод выбирается на 2014B по \(\bar{AP}_{module} - SE_{module}\), где SE — описательный штраф за разброс AP между модулями, *не* доверительный интервал. Если нет достаточного числа пригодных модулей, оценка использует общую AP валидации.
7. После выбора выбранные вероятности калибруются логистической моделью (Platt) **только на валидационных ответах**. Затем производится окончательная проверка на holdout.

## 4. Математические определения

Обозначим \(x_i^{(w)}(t)\) — агрегаты поведения студента \(i\) за дни \([t-w+1,t]\), \(w\in\{14,28,56,84\}\), а \(f_w(x_i^{(w)}(t))\) — вероятность риска, выданную моделью окна \(w\).

Для фиксированного метода \(\hat w=\arg\max_w AP_{val}(f_w)\).

Для равномерного ансамбля \(p_i^{ens}=\frac{1}{4}\sum_w f_w(x_i^{(w)}(84))\).

Для валидационно-взвешенного ансамбля \(p_i^{wt}=\frac{\sum_w a_w f_w(x_i^{(w)}(84))}{\sum_w a_w}\), где \(a_w=\max(AP_{val,w}-\pi_{val},\varepsilon)\) и \(\pi_{val}\) — распространённость положительного исхода на валидации.

Адаптивная функция окна (до просмотра тестовых меток):

\[Q_i(w)=\ln\left(1+\frac{clicks_{i,w}}{w}\right)+0.8\ln\left(1+\frac{events_{i,w}}{w}\right)+0.35\ln(1+assessments_{i,w})-0.15\left(\frac{w}{14}-1\right).\]

Выбирается \(w_i^*=\arg\max_w Q_i(w)\). Это **априорная исследовательская эвристика**, не доказанно оптимальный алгоритм и не установленная научная новизна.

## 5. Отчётность и неопределённость

На holdout рассчитаны: AP, ROC-AUC, Brier, ECE с 10 интервалами; ECE зависит от биннинга и сама по себе не доказывает калиброванность. Для сравнения с фиксированным окном используется парный bootstrap по `id_student` (учитывает повторные записи одного человека), 95% интервал \(\Delta AP\). Это условная неопределённость для одной независимой когорты, не межуниверситетская воспроизводимость.

Для индивидуальных прогнозов рассчитывается только **агрегированный** эксперимент с отказом от ответа: принимается прогноз, если \(|p_i-0.5|\ge\tau\) при \(\tau\in\{0,0.1,0.2,0.3\}\). Представляются доля принятых случаев, число принятых и их классификационная ошибка. Индивидуальные вероятности и анонимные `id_student` через веб-API не выдаются.

## 6. Противопоставление литературе

Опубликованная в июле 2026 г. работа Wu, Duan & Luo, PLOS ONE, DOI https://doi.org/10.1371/journal.pone.0352867, уже применяет OULAD для калибровки раннего прогноза, uncertainty/selective prediction, fairness-аудита. Сам факт использования перечисленных методов **не может считаться научной новизной**. Потенциальная исследовательская добавка EduRisk должна быть проверена отдельно: влияние качества/длины индивидуальной истории на правило выбора прогнозной стратегии при переносе между курсами и временными периодами.

## 7. Требования к окончательному результату

- Заполнить `data/oulad/raw` оригинальными семью CSV из официального набора.
- Зафиксировать SHA-256 и версии библиотек; исследовательский отчёт `reports/external_oulad_summary.json` сохраняет хеши источников.
- Повторить для логистической регрессии и случайного леса.
- При необходимости повторить на новых разбиениях модулей и в другом университете, иначе перенос не доказан.
- До проверки юридических оснований не использовать реальные персональные ведомости ТУСУР, и не применять модель для автоматических решений, влияющих на студентов.
