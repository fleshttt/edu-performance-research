# Методика анализа истории успеваемости — версия 0.2

**Тема диссертации:** «Модели и алгоритмы мониторинга и прогнозирования академической успеваемости обучающихся для поддержки принятия решений в образовательном процессе».  
**Специальность:** 1.2.1 «Искусственный интеллект и машинное обучение».  
**Статус:** прототип алгоритмической и экспериментальной части, а не доказанная научная новизна.

## 1. Что проверяем

Исследовательский вопрос: увеличивает ли использование данных о **динамике** успеваемости за несколько учебных периодов качество прогноза академического риска в следующем периоде по сравнению с использованием только текущих показателей? Исходный критерий риска — средняя оценка ниже 3,0 по синтетической шкале 2–5 в периоде `t+1`.

Нулевая гипотеза H0: исторические признаки не повышают качество вневыборочного прогноза по сравнению с признаками текущего периода. Рабочая гипотеза H1: динамика за последние три периода может улучшить AP / ROC-AUC / Brier; направление и величина эффекта должны быть установлены экспериментально. Отдельно необходимо проверить устойчивость между образовательными программами, учебными периодами и группами при наличии разрешённых данных.

Демонстрационный порог 3,0 и набор признаков **не согласованы с вузом** и служат только для исследования конструкции метода.

## 2. Структура записи

Единица наблюдения — пара `(student_id, term_index)`. Период `t` описывают уже известные результаты обучения к концу семестра: текущая оценка, посещаемость, выполнение заданий, опоздания сдач и доля закрытых кредитов.

В базе должны существовать отдельные строки на каждый учебный период, а не просто одна строка с итоговой оценкой. Пропущенный семестр не заменяется соседним, и лаг 1 всегда обозначает именно `t−1`. Идентификатор студента нужен только для группировки, **не** является обучающим признаком. Метка `next_term_low_performance` вычисляется по `t+1`, используется для обучения/оценки и не включается в расчёт признаков.

## 3. Формирование признаков

Для каждого периода `t` используются только строки конкретного студента с номерами `t−2`, `t−1` и `t`. Признаки:

| Признак | Метод расчёта | Если истории не хватает |
|---|---|---|
| `grade_lag_1` / `grade_lag_2` | Оценки именно в `t−1` и `t−2` | `NaN` |
| `grade_mean_3` | Среднее доступных оценок за `t−2…t` | `NaN`, если все оценки отсутствуют |
| `grade_std_3` | Стандартное отклонение оценок за три периода, `ddof=0` | `NaN` при менее чем 2 оценках |
| `grade_slope_3` | Наклон МНК-регрессии `оценка ~ индекс периода`, по имеющимся точкам из `t−2…t` | `NaN` при менее чем 2 оценках |
| `grade_change_1` | Оценка `t` минус оценка `t−1` | `NaN` без пары периодов |
| `attendance_change_1` | Посещаемость `t` минус посещаемость `t−1` | `NaN` без пары периодов |
| `assignment_change_1` | Выполнение заданий `t` минус выполнение `t−1` | `NaN` без пары периодов |
| `credits_change_1` | Доля кредитов `t` минус доля в `t−1` | `NaN` без пары периодов |
| `history_terms_available` | Число доступных непустых оценок в окне `t−2…t` | 0–3 |

Числовые пропуски заполняются медианой, вычисленной **только на обучающей части**. Никакие данные из валидационной или тестовой выборки не участвуют в расчёте этой медианы. Окно истории и формулы — начальные решения для сравнительного эксперимента; они не являются утверждением оптимальности.

## 4. План сравнения

Сценарий A (срез): `term_index`, посещаемость, выполнение заданий, просрочки, средняя оценка и доля закрытых кредитов в периоде `t`.

Сценарий B (история): те же текущие показатели **плюс** десять исторических признаков, описанных выше.

В каждом сценарии используются одни и те же реализации логистической регрессии и случайного леса с фиксированными гиперпараметрами. Добавлен DummyClassifier как контроль частоты риска. В отличие от версии 0.1, `grade_trend` исключён из сценария «срез», поскольку он уже учитывает прошлый семестр; его содержательное значение пересчитывается в `grade_change_1` для сценария B.

- Обучение: семестры `t = 1, 2, 3` (для меток нужны наблюдения будущих семестров `2, 3, 4`).
- Валидация: `t = 4`, метка из семестра 5.
- Отложенный тест: `t = 5`, метка из семестра 6. **Тестовые метки не используются для отбора модели и признаков.**
- Отбор модели: максимальная AP на валидации, затем минимальный Brier; фиксированное правило до просмотра теста.
- Отчёт: AP, ROC-AUC, Brier, precision, recall, F1, матрица ошибок и численность положительного класса. Ключевая проверка — **парное сравнение каждого алгоритма** с историей и без истории.

Здесь одни и те же студенты могут присутствовать в разных семестрах — это сценарий прогноза для **продолжающих обучение**. При перенесении решения на новых студентов нужен независимый отдельный эксперимент с разбиением по студентам. При получении реальных данных необходимы несколько временных тестовых окон, доверительные интервалы / бутстрэп по студентам и проверка стабильности результата. Отдельно исследуются пропуски, изменение учебных программ, сдвиги распределений и возможная несбалансированность меток.

## 5. Техническая проверка отсутствия утечки

Модуль `src/edurisk/history.py` не читает `next_term_low_performance`: вычисление основано только на наблюдениях. Тест `test_no_future_or_target_leakage` меняет целевые метки и оценки в будущем периоде и проверяет неизменность исторических признаков более раннего периода. Тест на пропущенный семестр исключает подмену `t−1` более ранним наблюдением.

Ограничение: вычислительный эксперимент на синтетических данных не подтверждает применимость к реальному вузу. Результаты должны быть повторены по согласованному, юридически допустимому обезличенному набору и обсуждены с научным руководителем.
