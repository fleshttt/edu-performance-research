# 03. Протокол данных и вычислительного эксперимента (черновик)

## Схема демонстрационного набора

| Поле | Смысл | Условия |
|---|---|---|
| `student_id` | синтетический псевдоидентификатор | только для связывания периодов, **не признак** |
| `term_index` | порядковый номер периода (1–5) | известен в момент прогноза |
| `attendance_rate` | доля посещений за период | 0–1, только текущий/прошлый период |
| `assignment_completion_rate` | доля выполненных заданий | 0–1 |
| `late_submission_rate` | доля работ с просрочкой | 0–1 |
| `current_avg_grade` | средняя оценка за текущий период | 2–5 (демонстрационный формат) |
| `grade_trend` | разница между текущим и предыдущим средними баллами | вычислять без будущих оценок |
| `credits_completion_rate` | доля освоенных учебных кредитов за период | 0–1 |
| `next_term_low_performance` | фактическое событие в **следующем** периоде | `1` при средней оценке ниже 3,0; только целевая метка |

## Методический контроль

**Избежать утечек:** зафиксировать момент прогноза; исключить итог следующего периода, статус задолженности и любые признаки, вычисляемые из будущих событий. Преобразования (нормализацию, заполнение пропусков) обучать на train, а не на всём наборе. Не выбирать модель по тестовым меткам.

**Разделение:** сначала проверка по времени (семестры 1–3, 4, 5). На реальных данных пересмотреть границы, учитывать доступность меток, последовательность формирования записи и даты закрытия ведомостей. Дополнительно предусмотреть испытание на новых людях и новых учебных потоках; временная проверка этого не заменяет.

**Метрики:** AP и ROC-AUC для способности ранжирования; Brier и диаграммы калибровки для вероятностей; recall, precision, F1 и матрица ошибок для конкретного операционного порога. Отдельно анализировать долю класса риска, интервалы неопределённости и влияние выбранного порога.

**Базовые подходы:** DummyClassifier, LogisticRegression, RandomForest. Приоритет — воспроизводимое сравнение и анализ недостатков, а не максимум одной метрики на одной выборке.

**Чувствительность:** пропуски, дисбаланс, изменение программы обучения, небольшие потоки, разная длина истории, смена шкалы оценок, новая популяция студентов. Не включать чувствительные персональные признаки без отдельного правового и этического обоснования.

## Реальные данные — пока не подключены

Нужно согласовать источник и цель использования данных, требования университета и применимые правила защиты персональных данных. Не загружать в облачные репозитории или открытые сервисы ФИО, ведомости и записи, позволяющие идентифицировать учащихся. Одного удаления ФИО может быть недостаточно для обезличивания. Доступы, хранение, журналирование и удаление данных определяются до получения набора.

## Важное ограничение применения

Числовой риск — не индивидуальный диагноз, не дисциплинарная оценка и не основание для автоматических неблагоприятных решений. Результат может поддерживать проверку человеком в пределах утверждённой образовательной процедуры.
